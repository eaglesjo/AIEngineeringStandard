# AI Engineering Standard 2.3.0

## Runtime Conformance & Evidence Provenance

This release advances the runtime conformance harness and makes execution evidence more explicit, attributable, and reproducible.

### Highlights

- Emit complete conformance evidence records for dry-run and executed runtime scenarios.
- Generate unique action and evidence identifiers, with optional parent-action linkage.
- Preserve repository revision and tri-state dirty-state provenance.
- Validate evidence before writing it, including timestamp ordering and canonical check/observation structure.
- Require evidence identity in trace records and align the JSON Schema with the Python validator.
- Distinguish an undeclared protected target from a successful protected-file integrity observation.
- Parse command templates before inserting scenario prompt text and require the prompt placeholder to occupy a complete argument token.
- Use unique temporary prompt files and clean them up safely.
- Accept permission-denial evidence only from explicit machine-readable denial codes; do not infer multiple independent permission results from one generic denial event.
- Add deterministic fake-runtime regression coverage for evidence provenance, prompt argument boundaries, and permission-denial handling.
- Add a dedicated Runtime Harness GitHub Actions matrix for Ubuntu, macOS, and Windows using Python 3.12.
- Verify the immutable source SHA checked out by the OS matrix before running schema and validation tests.

### Validation evidence

- Runtime Harness OS Matrix: Ubuntu, macOS, and Windows jobs completed successfully on implementation commit `8086026f47d593d584eb15a26ccff07b7360a364`.
- AI Engineering Standard CI: all 11 jobs completed successfully on the same implementation commit.
- The runtime harness tests use deterministic fake-runtime fixtures. No live Codex runtime was invoked and no paid runtime tokens were consumed.
